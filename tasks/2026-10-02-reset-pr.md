# Reset PR per exercise

## Ask
Mr. Roni 2026-10-02 3:26pm (topic 620): "Allow the user to be able to reset their PR for a certain exercise. Which
can be done on the exercise itself." Answers 3:33pm: reset = clear it, the next logged set becomes the new PR
whatever the weight; confirm first, like delete-exercise.

## Done criteria
- [x] Exercise info popup: "Reset PR (55lb × 15)" button (only when a PR is stored), above Delete/Hide.
- [x] Confirm first ("Reset your PR for <name> (<PR>)? The next set you log becomes your new PR ... can't be
      undone."), Cancel changes nothing.
- [x] Reset deletes jk_prs[exId] (and the cardio/hold record for runs/holds). History, sets, totals, prCount
      untouched (byte-identical in the test).
- [x] Next logged set becomes the PR (commitPRs sees no record): 20 lb x 5 after a 55 x 15 reset.
- [x] Sync: S.s marks dirty -> normal sync-on-change. New backup key jk_prReset {exId: ISO}.
- [x] Not resurrected: mergeBackup keeps the LATEST reset per exercise and drops each side's records dated before
      it BEFORE the best-wins merge (first version filtered after, which lost the new PR to the heavier stale one;
      caught by the test). Same idea as jk_prRepair, separate key because repair marks keep the EARLIEST time.
      enforcePRResets() at launch removes an old record written back by a login/file restore.
- [x] Unaffected (computed from history, not jk_prs): badges and tiers, Past PRs, PR counts per workout, Top PR
      card, Muscle Map. Affected: the library's PR line for that exercise and the "PRs Set"/"Total PRs"/board PR
      count (count of exercises with a stored PR) drop by one until the next set on it.
- [x] Watch: WATCH_BRIDGE row (APP-WIDE): keep jk_prReset, apply the drop rule.

## Tests
- [x] e2e resetPR (16 checks): button text, confirm text, cancel, cleared + marker, other PRs untouched, history
      identical, badges/Top PR unchanged, button gone, dirty, next set is PR, merge both directions keeps the new
      record, stale device merging the cloud drops its old one, latest-reset merge, restore cleaned at launch,
      Plank hold reset, no errors.
- [x] Full suite 913/913 on JK_PORT 8799.

## Limits
- A device still on an old build keeps its own old PR locally (and may upload it); devices with this build drop it.
- A CSV import of workouts dated before the reset can't set a PR for that exercise (records dated pre-reset drop).
